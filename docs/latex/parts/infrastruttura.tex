\section{Training Infrastructure}
\label{sec:infrastructure}

The training infrastructure is shared across all models and comprises the PyTorch dataset, the training pipeline, the experiment management system, loss functions, and evaluation utilities.

\subsection{Dataset and Data Loading}

The \texttt{ImageEnhancementDataset} class extends \texttt{torch.utils.data.Dataset} and manages loading of (degraded, clean) image pairs with random patch extraction.

\subsubsection{Patch Extraction}
Each image is divided into square patches of configurable size (typically $128\!\times\!128$ or $256\!\times\!256$). For each image, \texttt{patches\_per\_image} patches are extracted at random positions, so the effective dataset length is:
\begin{equation}
|\mathcal{D}| = N_{\text{images}} \times \text{patches\_per\_image}
\end{equation}
Images are cached via \texttt{@lru\_cache(maxsize=64)} to minimize disk I/O.

\subsubsection{Data Augmentation}
During training, geometric transformations are applied jointly to the degraded/clean pair via Albumentations:
\begin{itemize}
    \item HorizontalFlip ($p = 0.5$)
    \item VerticalFlip ($p = 0.5$)
    \item RandomRotate90 ($p = 0.5$)
\end{itemize}
Normalization maps pixels from $[0, 255]$ to $[-1, 1]$ via $x' = (x/255 - 0.5)/0.5$. During validation, only normalization is applied.

\subsubsection{DataLoader Configuration}
DataLoaders are configured with \texttt{pin\_memory=True} for asynchronous GPU transfers, \texttt{persistent\_workers=True} to avoid worker respawning, and \texttt{drop\_last=True} during training for constant batch sizes. A worker initialization function disables OpenCV threading and sets per-worker NumPy seeds.

\subsection{Loss Functions}

Three loss functions of increasing complexity are available.

\subsubsection{Combined Loss (L1 + SSIM)}
\begin{equation}
\mathcal{L}_{\text{combined}} = \alpha \cdot \mathcal{L}_{\text{L1}} + \beta \cdot (1 - \text{SSIM})
\label{eq:combined_loss}
\end{equation}
with default weights $\alpha = 0.84$, $\beta = 0.16$. Images are converted from $[-1,1]$ to $[0,1]$ for SSIM computation. For numerical stability under mixed precision (FP16), epsilon clamping and small Gaussian noise injection are applied to the SSIM computation.

\subsubsection{VGG Perceptual Loss}
The VGG Perceptual Loss~\cite{perceptualloss} uses a pretrained VGG-16 as a feature extractor. Features are extracted at configurable layers (\texttt{relu2\_2}, \texttt{relu3\_3} by default) and the loss is computed as weighted L1 distance in feature space:
\begin{equation}
\mathcal{L}_{\text{perceptual}} = \sum_{l \in \text{layers}} w_l \cdot \|\phi_l(\hat{x}) - \phi_l(x)\|_1
\end{equation}
where $\phi_l$ denotes VGG-16 features at layer $l$. VGG parameters are frozen and inputs are normalized with ImageNet statistics.

\subsubsection{Combined Perceptual Loss}
Unifies all three components:
\begin{equation}
\mathcal{L} = \alpha \cdot \mathcal{L}_{\text{L1}} + \beta \cdot (1 - \text{SSIM}) + \gamma \cdot \mathcal{L}_{\text{perceptual}}
\label{eq:perceptual_loss}
\end{equation}
Typical weights are $\alpha = 0.6$, $\beta = 0.25$, $\gamma = 0.15$. When $\gamma = 0$, the VGG network is not loaded into memory.

\subsection{Experiment Management}

Each experiment is saved in a timestamped directory:
\begin{small}
\begin{verbatim}
experiments/{model}/{degradation}/{timestamp}_{name}/
    checkpoints/   config.json   history.json
    samples/       logs/
\end{verbatim}
\end{small}

The system supports automatic \textit{forking}: if the configuration changes relative to the previous experiment, a new directory is created with its own metadata while copying the best checkpoint and training history from the parent. This enables systematic hyperparameter exploration with full traceability.

\subsection{Checkpointing}

Checkpoints save the complete training state: model weights, optimizer and scheduler states, current epoch, and metrics. At loading time, integrity validation checks all floating-point tensors for NaN/Inf values. In case of OOM errors during training, an emergency checkpoint is automatically saved before cleanup.

\subsection{Telegram Notifications}

A notification module sends training status updates (start, periodic progress, completion, early stopping, OOM errors) via Telegram Bot API, enabling remote monitoring of long-running experiments.
